# `@advanced-chat/components`

A framework-neutral chat UI library with a standards-based custom element and
typed Vue 3 components. Backend-agnostic: rooms, messages, files, audio,
reactions, replies / edits, typing indicators, themes, localization, and a
small set of composables for bringing your own UI.

This is the V3 successor to the original [`vue-advanced-chat`][v2]
package. V3 provides typed Vue 3 SFCs that consumers compose directly
and an official bundled light-DOM `<advanced-chat-components>` entrypoint for
framework-independent hosts. Slots, theming, and TypeScript ergonomics
no longer depend on Shadow DOM.

The public stable line remains `vue-advanced-chat@2.1.2`. These docs describe
`@advanced-chat/components@3.0.0-rc.1`, a pre-GA V3 release candidate. Do not
treat the V3 API as the stable v2 package or as a drop-in upgrade.

[v2]: https://github.com/advanced-chat/advanced-chat-components/tree/v2

## When to use it

Reach for this package when you want a chat surface that:

- Renders in a normal Vue 3 / Vite / Nuxt project (no Shadow DOM,
  no `register()` step, no JSON-stringified props).
- Composes downward — drop `AdvancedChat` for the all-in-one
  experience, drop down to `Chats + Chat` when you need a custom
  layout, drop down to the primitives (`ChatHeader`, `ChatFooter`,
  `Message`, `MessageTemplate`, …) when you need full control.
- Lets you keep ownership of the data layer. The library never
  fetches or persists anything; you wire your backend via props
  (`chats`, `messages`) and events (`fetch-messages`,
  `send-message`, `chat-action-handler`, …).
- Has an honest, typed contract. Props and event payloads ship in generated
  declarations, while Storybook documents each public slot and its bindings.

## When _not_ to use it

- You need a hosted chat with backend included — this is UI only.
- You require Shadow DOM isolation. The V3 web component intentionally
  renders in light DOM so host CSS, accessibility tools, and framework
  integrations share one document tree.
- You need native React or Svelte components rather than the framework-neutral
  custom-element entrypoint. This package does not provide native adapters.

## What's in the package

- 28 components, each individually importable, plus the bundled web
  component entrypoint.
- 5 composables for the state machines that back the built-in
  components (you can build custom autocomplete, selection,
  pagination, search, and reply-edit surfaces without re-deriving
  the logic).
- A theming layer based on CSS custom properties: light, dark,
  auto (`prefers-color-scheme`), or your own override map.
- A localization plugin that takes a `Partial<Strings>` so you only
  override what you care about.
- A markdown / mention / linkify formatter (`formatText`) you can
  use to render messages elsewhere in your app.
