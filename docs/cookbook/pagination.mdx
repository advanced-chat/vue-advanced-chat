# Pagination

`Chat` and `Chats` both fire pagination events when the user
scrolls near the boundary of the list. The host responds by
fetching older items and prepending (for messages) or appending
(for chats) them to the reactive ref.

## Messages

`Chat` emits `fetch-messages` when the scroll position is within
60 px of the top of the messages list, suppressed while
`loadingMessages` or `messagesLoaded` is `true`.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import type { Message } from '@advanced-chat/components'

const messages = ref<Message[]>([])
const loadingMessages = ref(false)
const messagesLoaded = ref(false)

const fetchOlder = async () => {
  if (loadingMessages.value || messagesLoaded.value) return
  loadingMessages.value = true

  const oldestId = messages.value[0]?.id
  const next = await api.getMessages({ before: oldestId, limit: 50 })

  // Prepend — older messages go to the top of the array.
  messages.value = [...next, ...messages.value]
  messagesLoaded.value = next.length === 0
  loadingMessages.value = false
}
</script>

<template>
  <Chat
    :current-user="currentUser"
    :chat="activeChat"
    :messages="messages"
    :loading-messages="loadingMessages"
    :messages-loaded="messagesLoaded"
    @fetch-messages="fetchOlder"
  />
</template>
```

### Important: never mutate the array shape during a load

The library reads `messages.length` to detect new arrivals. If you
swap the entire ref while a fetch is in flight, the auto-scroll
heuristic gets confused. Either:

- Append in place (`messages.value = [...older, ...messages.value]`),
  which is what the snippet above does. Vue notices the new length
  and re-runs the watcher.
- Or set `messages.value = await fetchAll()` *once*, with the
  full list, and never paginate. (Fine for small chats but not
  what most apps want.)

### Scroll-position preservation

The library does **not** preserve scroll position when older
messages prepend. The default browser behavior is to keep the
*pixel offset from the top* constant — which means the user will
see the old top message scroll downward by the height of the
newly-prepended block. Consumers who want sticky-relative
preservation should snapshot `scrollTop + scrollHeight` before the
load and restore it after `nextTick`:

```ts
const beforeLoad = (el: HTMLElement) => {
  const offset = el.scrollHeight - el.scrollTop
  return offset
}

const afterLoad = (el: HTMLElement, offset: number) => {
  el.scrollTop = el.scrollHeight - offset
}
```

Wire this around your `fetchOlder` call by grabbing
`document.querySelector('.vac-container-scroll')` (or use the slot
escape hatch to wrap `Chat` and capture the ref yourself).

## Chats

`Chats` emits `fetch-more-chats` when the chats list scrolls
within 100 px of the bottom, suppressed while `chatsLoaded` is
`true`. The pattern is the inverse — older chats append:

```ts
const chats = ref<Chat[]>([])
const chatsLoaded = ref(false)
const loadingMoreChats = ref(false)

const fetchMoreChats = async () => {
  if (loadingMoreChats.value || chatsLoaded.value) return
  loadingMoreChats.value = true

  const oldestId = chats.value[chats.value.length - 1]?.id
  const next = await api.getChats({ after: oldestId, limit: 25 })

  chats.value = [...chats.value, ...next]
  chatsLoaded.value = next.length === 0
  loadingMoreChats.value = false
}
```

`Chats` also has a `minimumVisibleChats` prop (default `10`). When
the local list (after applying the search filter) falls below
that, the component will eagerly call `fetch-more-chats` even
without the user scrolling — useful for narrow viewports where the
sidebar shows fewer chats than the threshold by default.

## Combining with `useInfiniteScroll`

If you're rendering a *custom* list (not `Chats` / `Chat`),
`useInfiniteScroll` is the same machinery without the surrounding
component. See its
[reference page](?path=/docs/composables-useinfinitescroll--docs)
for the API.

## What `messagesLoaded` / `chatsLoaded` mean

These are "no more pages available" signals — once you flip them
to `true`, the components stop firing the `fetch-*` event. They
stay `true` until you flip them back (e.g. when the user switches
chats and the new chat starts at zero loaded messages).

The library doesn't infer them from anything. If your backend
returns 0 items, you flip the flag; if it returns a partial page
that you know is the last one, you can flip the flag eagerly
without waiting for an empty response.

## Auto-scroll interaction

`Chat`'s `autoScroll: { onReceive }` policy interacts with
pagination:

- When a new message arrives via append (`message[length-1]`
  changed), the library auto-scrolls if the user is at the bottom.
- When older messages prepend (`message[0]` changed), the library
  does **not** scroll — that would yank the user away from where
  they were reading.

If `autoScroll: { onReceive: false }`, the scroll-to-latest pill
appears for new messages instead of an automatic scroll.
