# Custom Action Menus

Four action menus are exposed across the surface, each driven by
an `Action[]` array prop. They share a single contract:
`{ id, label, icon?, ownMessageOnly? }`.

| Menu                                            | Prop location            | Event the host handles                                         |
| ----------------------------------------------- | ------------------------ | -------------------------------------------------------------- |
| Chat-row dropdown (per row in the chat list)    | `AdvancedChat` / `Chats` | `chat-action-handler: { chat, action }`                        |
| Chat-header overflow (top-right of active chat) | `AdvancedChat` / `Chat`  | `menu-action-handler: { chat, action }`                        |
| Per-message dropdown                            | `AdvancedChat` / `Chat`  | `message-action-handler: { action, message }`                  |
| Bulk-selection toolbar                          | `AdvancedChat` / `Chat`  | `message-selection-action-handler: { chat, action, messages }` |

The four payloads are intentionally different so a single
host-level handler doesn't accidentally shadow the wrong context.

## Define your actions

```ts
import type { Action } from '@advanced-chat/components'
import { REPLY_ACTION, EDIT_ACTION } from '@advanced-chat/components'

const chatActions: Action[] = [
  { id: 'archive', label: 'Archive' },
  { id: 'mute', label: 'Mute' },
  { id: 'leave', label: 'Leave chat' },
]

const headerActions: Action[] = [
  { id: 'add-participant', label: 'Add participant' },
  { id: 'view-info', label: 'Chat info' },
]

const messageActions: Action[] = [
  { id: REPLY_ACTION, label: 'Reply' },
  { id: EDIT_ACTION, label: 'Edit', icon: 'pencil', ownMessageOnly: true },
  { id: 'delete', label: 'Delete', icon: 'deleted', ownMessageOnly: true },
  { id: 'forward', label: 'Forward' },
  { id: 'pin', label: 'Pin' },
]

const selectionActions: Action[] = [
  { id: 'delete-many', label: 'Delete' },
  { id: 'forward-many', label: 'Forward' },
]
```

For `messageActions`, `ownMessageOnly: true` filters the action out for messages
authored by other users. Other menus ignore this field. It is useful for edit
and delete affordances but is not an authorization boundary.

`icon` resolves to a built-in `SvgIcon` name (`'pencil'`, `'deleted'`,
`'send'`, etc.). `Action` does not accept an icon component, and `Chat` does not
forward `MessageActions`' internal trigger slots. Use a supported built-in name,
omit the icon, or compose the lower-level components when custom menu chrome is
required.

## Wire the handlers

```vue
<script setup lang="ts">
import { AdvancedChat, EDIT_ACTION, REPLY_ACTION } from '@advanced-chat/components'
import type { Action, ChatModel, MessageModel, UserReference } from '@advanced-chat/components'

interface ActionsApi {
  archiveChat(id: ChatModel['id']): void
  muteChat(id: ChatModel['id']): void
  leaveChat(id: ChatModel['id']): void
  openAddParticipant(chat: ChatModel): void
  navigateTo(path: string): void
  deleteMessages(ids: MessageModel['id'][]): void
  forwardMessages(messages: MessageModel[]): void
  pinMessage(id: MessageModel['id']): void
}

const { currentUser, chats, activeChat, messages, api } = defineProps<{
  currentUser: UserReference
  chats: ChatModel[]
  activeChat: ChatModel | null
  messages: MessageModel[]
  api: ActionsApi
}>()

const chatActions: Action[] = [
  { id: 'archive', label: 'Archive' },
  { id: 'mute', label: 'Mute' },
  { id: 'leave', label: 'Leave chat' },
]
const headerActions: Action[] = [
  { id: 'add-participant', label: 'Add participant' },
  { id: 'view-info', label: 'Chat info' },
]
const messageActions: Action[] = [
  { id: REPLY_ACTION, label: 'Reply' },
  { id: EDIT_ACTION, label: 'Edit', icon: 'pencil', ownMessageOnly: true },
  { id: 'delete', label: 'Delete', icon: 'deleted', ownMessageOnly: true },
  { id: 'forward', label: 'Forward' },
  { id: 'pin', label: 'Pin' },
]
const selectionActions: Action[] = [
  { id: 'delete-many', label: 'Delete' },
  { id: 'forward-many', label: 'Forward' },
]

const onChatAction = ({ chat, action }: { chat: ChatModel; action: Action }) => {
  switch (action.id) {
    case 'archive':
      api.archiveChat(chat.id)
      break
    case 'mute':
      api.muteChat(chat.id)
      break
    case 'leave':
      api.leaveChat(chat.id)
      break
  }
}

const onHeaderAction = ({ chat, action }: { chat: ChatModel; action: Action }) => {
  switch (action.id) {
    case 'add-participant':
      api.openAddParticipant(chat)
      break
    case 'view-info':
      api.navigateTo(`/chat/${chat.id}/info`)
      break
  }
}

const onMessageAction = ({ action, message }: { action: Action; message: MessageModel }) => {
  // The built-in REPLY / EDIT actions already pre-fill the composer; you only need
  // to handle the rest.
  switch (action.id) {
    case 'delete':
      api.deleteMessages([message.id])
      break
    case 'forward':
      api.forwardMessages([message])
      break
    case 'pin':
      api.pinMessage(message.id)
      break
  }
}

const onSelectionAction = ({
  chat,
  action,
  messages,
}: {
  chat: ChatModel
  action: Action
  messages: MessageModel[]
}) => {
  switch (action.id) {
    case 'delete-many':
      api.deleteMessages(messages.map((message) => message.id))
      break
    case 'forward-many':
      api.forwardMessages(messages)
      break
  }
}
</script>

<template>
  <AdvancedChat
    :current-user="currentUser"
    :chats="chats"
    :chat="activeChat"
    :messages="messages"
    :chat-actions="chatActions"
    :header-actions="headerActions"
    :message-actions="messageActions"
    :selection-actions="selectionActions"
    @chat-action-handler="onChatAction"
    @menu-action-handler="onHeaderAction"
    @message-action-handler="onMessageAction"
    @message-selection-action-handler="onSelectionAction"
  />
</template>
```

## Selection mode

The selection toolbar is enabled by passing a non-empty
`selectionActions` array. While enabled:

- Clicking a message toggles its selection.
- The header is replaced by a toolbar showing each
  `selectionActions[i].label` with a count.
- Clicking a toolbar button fires
  `message-selection-action-handler` with the selected messages
  and clears the selection.
- Clicking "Cancel" in the toolbar emits `cancel-message-selection` and exits
  selection mode.

Pass an empty array (the default) to disable selection mode
entirely.

## Disabling actions for specific messages

Two `Message` flags suppress action menus on individual messages
without removing the actions globally:

```ts
import type { MessageModel, User } from '@advanced-chat/components'

const otherUser: User = {
  id: 'moderator',
  name: 'Moderator',
  status: { state: 'online' },
}

const messages: MessageModel[] = [
  {
    id: '1',
    sender: otherUser,
    content: 'A system announcement',
    createdAt: '2026-08-08T12:00:00.000Z',
    system: true,
    disableActions: true,
    disableReactions: true,
  },
]
```

| Flag               | Effect                                               |
| ------------------ | ---------------------------------------------------- |
| `disableActions`   | Hides the per-message dropdown menu on this message. |
| `disableReactions` | Hides the inline reaction picker on this message.    |

`system: true` already hides both by default (system messages
render as a centered pill, not a normal bubble).

## Building your own action menu

`ChatHeader` exposes `chat-options` and `MessageActions` exposes dynamic
`dropdown-icon_<message.id>` and `emoji-icon_<message.id>` trigger slots when
those lower-level components are rendered directly. `Chat` and `AdvancedChat`
do not forward those slots, so they cannot be used to replace menu triggers on
the complete chat surface.

For fully custom menus, compose the exported lower-level components or render
your own controls and call the same host handlers with `{ chat, action }` or
`{ action, message }`. You then own menu semantics, keyboard focus, positioning,
outside-click dismissal, and authorization. Treat action visibility as UX only:
the server must authorize every archive, edit, delete, moderation, and bulk
operation independently of the submitted action ID.
