# useLocalSearch

Wraps the package's small `filterItems` helper in a reactive
composable with a built-in escape hatch for server-driven search.
`Chats.vue` uses it for the chat-list search; the same shape works for any
collection with a field that can be converted to a string.

## Signature

```ts
import { useLocalSearch } from '@advanced-chat/components'

const { query, filtered, setQuery } = useLocalSearch<T>({
  items,
  field,
  custom,
  onSearch,
})
```

## Options

| Field      | Type                        | Description                                                                                                                                           |
| ---------- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `items`    | `MaybeRefOrGetter<T[]>`     | Items to filter.                                                                                                                                      |
| `field`    | `keyof T`                   | Item field to match against (e.g. `'name'`). The substring match is case- and accent-insensitive.                                                     |
| `custom`   | `MaybeRefOrGetter<boolean>` | When truthy, the local list passes through unfiltered — the host renders server-driven results. `query` is not updated either; only `onSearch` fires. |
| `onSearch` | `(query: string) => void`   | Fired with the supplied value on every `setQuery` call. Use this to call your backend search when `custom` is true.                                   |

## Returns

| Field      | Type                      | Description                                                                                        |
| ---------- | ------------------------- | -------------------------------------------------------------------------------------------------- |
| `query`    | `Ref<string \| null>`     | Stored local query. `null` means no local filter is active; custom-mode searches do not update it. |
| `filtered` | `ComputedRef<T[]>`        | Filtered items, or the raw input when `custom` is true.                                            |
| `setQuery` | `(value: string) => void` | Update the stored query when `custom` is false and always forward the value via `onSearch`.        |

## Example — local + server-driven hybrid

```vue
<script setup lang="ts">
import { computed, ref } from 'vue'
import { useLocalSearch, type ChatModel } from '@advanced-chat/components'

declare function searchChats(query: string): Promise<ChatModel[]>

const localChats = ref<ChatModel[]>([])
const remoteResults = ref<ChatModel[]>([])
const useRemote = ref(false)

const items = computed(() => (useRemote.value ? remoteResults.value : localChats.value))

const { filtered, setQuery } = useLocalSearch({
  items,
  field: 'name',
  custom: useRemote,
  onSearch: async (q) => {
    if (!useRemote.value) return
    remoteResults.value = await searchChats(q)
  },
})
</script>

<template>
  <input @input="setQuery(($event.target as HTMLInputElement).value)" />
  <label>
    <input v-model="useRemote" type="checkbox" />
    Search server
  </label>
  <div v-for="chat in filtered" :key="chat.id">{{ chat.name }}</div>
</template>
```

`searchChats` is intentionally declared as an app-owned API in this example;
replace it with your backend implementation.

## Notes

- The match is performed by `filterItems`, which lowercases both sides,
  normalizes them to NFD, removes combining diacritic marks, and then uses
  `String.prototype.includes`. For example, `cafe` matches `Café`.
- `setQuery('')` clears the filter and sets `query.value` to `null`.
  Your `onSearch` still fires with `''` so the backend knows to
  reset its result set.
- `custom` is checked when `setQuery` runs and inside `filtered`. While custom
  mode is active, new search values are emitted but not stored in `query`; if
  local mode is restored, its previous local query becomes active again.
