# useLocalSearch

Wraps the package's small `filterItems` helper in a reactive
composable with a built-in escape hatch for server-driven search.
`Chats.vue` uses it for the chat-list search; the same shape works
for any id-bearing collection.

## Signature

```ts
import { useLocalSearch } from '@advanced-chat/components'

const { query, filtered, setQuery } = useLocalSearch<T>({
  items,
  field,
  custom,
  onSearch,
})
```

## Options

| Field | Type | Description |
|---|---|---|
| `items` | `MaybeRefOrGetter<T[]>` | Items to filter. |
| `field` | `keyof T` | Item field to match against (e.g. `'name'`). The match is case-insensitive and substring-based. |
| `custom` | `MaybeRefOrGetter<boolean>` | When truthy, the local list passes through unfiltered — the host renders server-driven results. `query` is not updated either; only `onSearch` fires. |
| `onSearch` | `(query: string) => void` | Fired with the current query on every change. Use this to call your backend search when `custom` is true. |

## Returns

| Field | Type | Description |
|---|---|---|
| `query` | `Ref<string \| null>` | Current search query. `null` means no filter is active (i.e. the user cleared the input). |
| `filtered` | `ComputedRef<T[]>` | Filtered items, or the raw input when `custom` is true. |
| `setQuery` | `(value: string) => void` | Update the query and forward it via `onSearch`. |

## Example — local + server-driven hybrid

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'
import { useLocalSearch } from '@advanced-chat/components'

const remoteResults = ref<Chat[]>([])
const useRemote = ref(false)

const items = computed(() => (useRemote.value ? remoteResults.value : localChats.value))

const { filtered, setQuery } = useLocalSearch({
  items,
  field: 'name',
  custom: useRemote,
  onSearch: async (q) => {
    if (!useRemote.value) return
    remoteResults.value = await searchChats(q)
  },
})
</script>

<template>
  <input @input="setQuery(($event.target as HTMLInputElement).value)" />
  <label>
    <input v-model="useRemote" type="checkbox" />
    Search server
  </label>
  <div v-for="chat in filtered" :key="chat.id">{{ chat.name }}</div>
</template>
```

## Notes

- The match is performed by `filterItems`, which lowercases both
  sides and uses `String.prototype.includes`. Diacritics are
  preserved as-is — for accent-insensitive search you'd post-process
  `query` in your `onSearch` callback before sending it to the
  backend.
- `setQuery('')` clears the filter and sets `query.value` to `null`.
  Your `onSearch` still fires with `''` so the backend knows to
  reset its result set.
- `custom` is checked at the moment `setQuery` runs and again inside
  `filtered`, so flipping it on the fly does the right thing without
  a remount.
