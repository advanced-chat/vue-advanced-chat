# Public API

The public symbols exported from `@advanced-chat/components` and its separate
web-component entrypoint. Component pages under **Components** carry the full
prop/event/slot tables generated by Storybook autodocs; the cross-cutting
exports and custom-element boundary live here.

## Plugin

| Export                   | Kind     | Description                                                                                                          |
| ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------- |
| `AdvancedChatPlugin`     | function | Vue plugin factory. `app.use(AdvancedChatPlugin({ localization?, strings? }))` provides the localization dictionary. |
| `AdvancedChatOptions`    | type     | Options accepted by the plugin factory.                                                                              |
| `AdvancedChatPluginType` | type     | The plugin function shape (`Plugin` from `'vue'`).                                                                   |

## Components

The 28 components below are all exported as named values **and** as
their `*Props` / `*Events` interfaces.

| Component                            | Role                                                                      |

| `Chats`                              | Sidebar chat list with search, infinite scroll, and per-row actions.      |
| `ChatsSearch`                        | Search / add bar embedded in `Chats`.                                     |
| `ChatsItem`                          | Single chat row (avatar, last-message preview, unread badge).             |
| `Chat`                               | Active conversation: header + scroll list + composer + media preview.     |
| `ChatHeader`                         | Chat name, status, menu actions, message-selection toolbar.               |

| `ChatMessage`                        | Date dividers + new-messages divider around `Message`.                    |
| `Message`                            | Message bubble: text, files, audio, reply, reactions, actions.            |
| `MessageTemplate`                    | Markdown / mention / autolink rendering primitive.                        |
| `MessageReply`                       | Quoted-message preview.                                                   |
| `MessageFile` / `MessageFiles`       | Image / video / file attachment renderers.                                |
| `MessageActions`                     | Per-message dropdown + reaction picker.                                   |
| `MessageReactions`                   | Emoji-reaction pill row.                                                  |
| `MediaPreview`                       | Fullscreen image / video lightbox.                                        |
| `AudioPlayer` / `AudioControl`       | Audio playback + scrubber.                                                |

Per-component types follow the pattern `<ComponentName>Props` and
`<ComponentName>Events` (e.g. `ChatProps`, `ChatEvents`). A handful
of components also export ancillary types: `ChatFileItem`,
`InvalidFileReason`.

## Web component

The separate `@advanced-chat/components/web-component` entrypoint bundles Vue
and auto-registers the light-DOM `<advanced-chat-components>` tag on import. Import
`@advanced-chat/components/web-component/styles` alongside it.

| Export                           | Kind      | Description                                                                                                  |
| -------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------ |
| `registerAdvancedChat`           | function  | Registers a custom tag, or updates options for future mounts of a tag previously managed by this entrypoint. |
| `createAdvancedChatElement`      | function  | Creates an unregistered custom-element constructor for hosts that manage their own registry.                 |
| `DEFAULT_CUSTOM_ELEMENT_TAG`     | constant  | `'advanced-chat-components'`.                                                                                |
| `AdvancedChatHTMLElement`        | interface | `HTMLElement` plus typed `AdvancedChat` properties and typed event listener overloads.                       |
| `AdvancedChatEventMap`           | type      | Maps every public event name to its typed `CustomEvent<Detail>`.                                             |
| `AdvancedChatElementConstructor` | interface | Constructor returning `AdvancedChatHTMLElement`.                                                             |
| `RegisterAdvancedChatOptions`    | interface | Plugin `localization` / `strings` options plus an optional `tagName`.                                        |

Objects and arrays must be assigned as DOM properties. Each event payload is
available directly at `event.detail`; single-argument Vue emits are not exposed
as one-element arrays. Following the DOM `CustomEvent` contract, a no-payload
event has `detail === null`. Public
events use `bubbles: true` and `composed: true`, allowing event delegation from
an application shell or across a host shadow root.

`@advanced-chat/components/web-component/core` exports the same registration
and type API without registering a tag during module evaluation. Use it for
SSR-safe imports, alternate tag names, or applications that require explicit
startup control. The default `/web-component` entry remains auto-registering.

The default import performs registration before user code calls
`registerAdvancedChat()`. Supplying options in a later call updates the managed
options object used by future element mounts only. Existing mounted elements
keep their initialized plugin values. If another constructor already owns the
tag, options are rejected rather than silently ignored.

## Composables

State machines that back the built-in components, exported so
consumers can build custom surfaces without re-deriving the logic.
Each has its own page under **Composables** in the sidebar.

| Export                | Description                                                       |
| --------------------- | ----------------------------------------------------------------- |
| `useAutocomplete`     | Active-index state machine for floating menus.                    |
| `useMessageSelection` | Bulk-selection state for any id-bearing list.                     |
| `useReplyEdit`        | Composer state for the built-in `REPLY_ACTION` / `EDIT_ACTION`.   |
| `useInfiniteScroll`   | `IntersectionObserver` helper for pagination.                     |
| `useLocalSearch`      | Reactive `filterItems` wrapper with a server-driven escape hatch. |

Each ships a matching `Use<Name>Options` and `Use<Name>Return` type.

## Domain models

| Export             | Kind | Description                                                                                                                                                            |
| ------------------ | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ChatModel`        | type | The chat shape passed to `Chats` / `Chat` / `AdvancedChat`. Aliased so it doesn't shadow the `Chat` _component_.                                                       |
| `ChatReference`    | type | `{ id }`-only projection.                                                                                                                                              |
| `MessageModel`     | type | The message shape passed to `Chat.messages`. Aliased away from the `Message` component.                                                                                |
| `MessageReference` | type | `{ id }`-only projection.                                                                                                                                              |
| `MessageStatus`    | type | `'sending' \| 'sent' \| 'delivered' \| 'read' \| 'failed'` — a single source of truth for the delivery state machine (replaces the four overlapping booleans from v2). |
| `MessageSummary`   | type | Non-recursive projection used by `Chat.lastMessage` and `Message.reply`.                                                                                               |
| `MessageFileModel` | type | Pending or sent file attachment. Aliased away from the `MessageFile` component.                                                                                        |
| `User`             | type | Chat participant.                                                                                                                                                      |
| `UserReference`    | type | `{ id }`-only projection used wherever the full `User` is overkill.                                                                                                    |
| `Action`           | type | `{ id, label, icon?, ownMessageOnly? }` — items rendered in the four action menus (header, message, chat-row, selection toolbar).                                      |
| `Id`               | type | `string`. Numeric backend ids should be stringified at the boundary.                                                                                                   |

`Message.sender` is a full `User`; it is not a `UserReference`. In contrast,
the viewer-facing `currentUser` component prop accepts the minimal
`UserReference` shape (`{ id }`). Chat participants in `chat.users` provide the
full user records used for names, avatars, presence, and mention resolution.

## Action constants

The two action `id`s `Chat` recognizes internally (and still emits
`message-action-handler` for so consumers can chain custom logic on
top):

| Export              | Value     | Description                           |
| ------------------- | --------- | ------------------------------------- |
| `REPLY_ACTION`      | `'reply'` | Pre-fills `ChatFooter`'s reply state. |
| `EDIT_ACTION`       | `'edit'`  | Pre-fills `ChatFooter`'s edit state.  |
| `BuiltInActionName` | type      | Union of the two strings above.       |

Use these constants in your `messageActions: Action[]` rather than
the magic strings.

| ------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------- |
| `Localization`           | type       | `'en' \| 'auto'`.                                                                                                   |

## Send and edit payloads

Both events preserve selected mentions in `content` as `<@id>` tokens and add
the resolved, deduplicated users as `mentionedUsers: User[]`:

```ts
type SendPayload = {
  content: string
  files: ChatFileItem[]
  mentionedUsers: User[]
  reply?: MessageModel | null
}

type EditPayload = {
  messageId: string
  content: string
  files: ChatFileItem[]
  mentionedUsers: User[]
}
```

`ChatFooter` owns pending `ChatFileItem.localUrl` object URLs until a file is
removed/reset or an event is emitted. Send/edit transfers ownership to the
listener; the listener must revoke each emitted object URL after its upload or
optimistic preview no longer needs it.

## Operational state

`AdvancedChat.status` accepts `ready`, `loading`, `empty`, `error`, `offline`,
`reconnecting`, and `permission-denied`. Loading, empty, error, and permission
denied replace the chat surface with a state panel. Offline and reconnecting
show a non-blocking banner and preserve history/navigation. `statusMessage`
overrides the default copy, `retryLabel` labels the error action, `retry` fires
when that action is activated, and `composerDisabled` independently makes the
composer read-only.

`AdvancedChat` observes its own container width. At 768 px or narrower it
shows one pane at a time, hides the chat list after a chat opens, and uses the
header toggle to return to the list. The breakpoint is currently fixed.

## Stylesheet entrypoint

```ts
import '@advanced-chat/components/styles'
```

Imports the bundled `dist/components.css`. The component palette uses CSS
custom properties, so consumer overrides follow the normal cascade without a
Shadow DOM boundary.
